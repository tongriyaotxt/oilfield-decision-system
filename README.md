# 油井生产智能决策系统

> 一个**可运行**的油田生产智能化原型：从指标口径建模，到自然语言取数，到开关井决策、
> 故障预判、自动派工、AI 班报，全部串成一条可复算、可审计的闭环。
>
> 现状：**逻辑可跑、契约完备、数据是合成的**。它是测试台与工程骨架，不是现场系统。
> 距离生产的差距见 [§9 成熟度](#9-成熟度与已知限制)。

---

## 1. 它解决谁的什么问题

| 角色 | 原来怎么做 | 现在 |
|---|---|---|
| 数据员 | 一句取数要写 SQL、对口径、等人天 | 一句话出数，口径自动披露，可复算 |
| 值班长 | 靠经验拍"哪口井该关、哪口该开" | 系统给目标时率 + 开停小时 + 证据，A/B/C 分级授权 |
| 工艺/地质 | 泵效、含水、单耗各说各数 | 18 个指标、58 个别名收敛到唯一 IRI + 唯一公式 |
| 厂长 | 月底才发现产量掉、电费涨 | 故障预判提前给"预计 N 天触线"，班报每天自动生成 |

## 2. 能力清单（都有实测数字）

**① 自然语言取数**
一句话 → 结构化计划 → 本体编译 SQL → 结果 + 口径四件套（公式/单位/时间口径/踩坑提示）。
6 个示范问题全部跑通，含 3 个陷阱：比率加总、分母为 0、趋势题。

**② 口径治理**
18 个指标（原子 10 + 派生 8）、58 个别名、7 个维度。三条铁律写进本体：
比率不可加（含水率必须 `SUM(水)/SUM(液)`）、时间口径不可混（生产日/自然日/月末盘库）、别名必须收敛。

**③ 开关井决策**
5 条规则 + 5 个约束，输出"开几小时、停几小时、为什么"。
沙箱 14 天 × 10 井实测：**产液 +65.5%、产油 +63.4%、吨液电耗 −7.8%、启停 −45%**，
增量净收益 **+1.1 万元/日**（10 口井）。

**④ 决策门禁**
每条决策必须带"规则 + ≥2 个证据指标 + 置信度 + 时间"，否则不许下发。
实测 24 条决策 conforms = True；注入 3 条坏决策被拦下 13 条违规。

**⑤ 回归闭环**
回采 7 天实际值比对，偏差 >15% 自动降级人工；按井标定负载系数后，
预测偏差 **11.9% → 9.3% → 5.0%**（再加启动冲击项）。

**⑥ 自主控制接口**
命令幂等、`deadline`、`expected_state` 回执校验、失败回滚、A/B/C 授权、灰度、审计。
一轮实测：下发 8 条 → 4 成功、4 等审批、1 次重试成功、1 次审批后回滚。

**⑦ 模拟生产环境**
现场仿真 + 时序库（含漂移/缺口/死值/时钟偏移）+ RTU（阀卡死/通信超时/联锁），
三策略对照（baseline / shadow / agent）。影子模式与人工经验规则一致率 **51.2%**，
分歧集中在"泵效 15~30%"——正是间开收益最大的区间。

**⑧ 故障预判**
趋势（最小二乘斜率）+ 阶跃（3 日 vs 11 日）+ 数据质量，7 类故障。
24 口井扫出 20 条风险：2 条断脱（critical，立即）、1 条气锁、3 条阀卡涩、14 条抽汲过剩（单列，不派检修）。

**⑨ 自动派工**
技能匹配 + 距离罚分 + 负荷 → 选人；超时 30min 升级值班长；拒单自动派生备件申请。
实测 6 单：完成 4、升级 1、拒单 1，审计 22 条。

**⑩ AI 班报（真模型接入）**
确定性代码算事实表 → 模型只写语言 → **机器核对数字**：报告里每个数字必须能在事实表找到，
井号必须在风险清单内，`N 口井` 必须等于事实井数。
真模型输出通过核对；编造版（1.8 t/d、乙区-07、30 口井）被拒收并回退模板。

## 3. 它**不**做什么（边界）

| 不做 | 原因 |
|---|---|
| 提高单井产能上限 | 间开不创造供液，产量天花板就是 `qi`；增产靠老井复查、措施、CCUS |
| 替代执行机构 | 阀门、变频器、RTU 是硬件；本系统只下发命令并校验回执 |
| 秒级实时控制 | 2 秒以内的联锁归 SIS，本系统不进入该环 |
| 替人做经营决策 | 关停、措施、注采比由人签字，系统只给 C 类建议与报价 |
| 覆盖安全联锁 | SIS 优先级最高，Agent 被拒记录在审计 `sis.refused` |
| 对未建模指标作答 | 未注册指标直接拒绝，不用猜测值回答 |

## 4. 架构

```
                     ┌────────────── 业务侧（确定性，可审计）──────────────┐
用户提问 ──①LLM──► Plan(JSON) ──②本体校验──► ③编译SQL ──④执行 ──⑤校验 ──► 回答
                                    │
                                    └─ 不合格直接拒绝（不猜）

时序数据 ──► 特征聚合 ──► 规则决策 ──► SHACL 门禁 ──► 命令总线 ──► RTU ──► 现场
                │              │            │             │
                │              │            │             └─ 回执/重试/回滚/审计
                │              │            └─ 可追溯性（规则+证据+周期+置信度）
                │              └─ 供液比 / 泵效 / 时率 / 日产油
                └─ 口径来自 analytics-core.ttl（唯一来源）

            ┌──────────── 模拟生产环境（sim/）────────────┐
            │ Plant 物理模型 + 递减/含水/磨损 + 抽空保护    │
            │ Historian 时序库 + 脏数据注入                 │
            │ RTU 阀卡死 / 通信超时 / SIS 锁定              │
            └──────────────────────────────────────────────┘
```

### 分层职责

| 层 | 目录 | 职责 | 变更频率 |
|---|---|---|---|
| 口径层 | `ontology/analytics-core.ttl` | 指标定义、公式、可加性、时间口径、别名 | 低（评审制） |
| 决策层 | `ontology/decision-core.ttl` | 规则、阈值、动作、约束 | 低（评审制） |
| 门禁层 | `ontology/*-shapes.ttl` | 决策/数据/无人化的合规校验 | 低 |
| 契约层 | `ontology/control-core.ttl`、`fault-core.ttl` | 命令、回执、授权、工单、技能 | 低 |
| 执行层 | `scripts/*.py` | 取数、决策、派工、报告 | 中 |
| 环境层 | `sim/*.py` | 现场仿真、时序库、RTU | 仅测试 |

## 7. 六个核心设计原则

1. **口径单一来源**：指标只在 `analytics-core.ttl` 定义一次，SQL 由本体编译，报表与 Agent 共用。
2. **AI 只做翻译**：模型只输出 `Plan(JSON)`，不写 SQL、不算数、不定口径。不合格直接拒绝，不猜。
3. **决策确定性**：规则 + 阈值 + 约束求解，全部可复算；没有黑箱。
4. **单向安全**：自动动作只允许"切断/降级/回退/隔离"，提高时率与复产必须人工审批。
5. **门禁先于下发**：决策不带证据不许下发；报告出现事实表外的数字直接拒收。
6. **坏数据比没数据更危险**：质量位为 Bad 的点不进入任何决策输入；覆盖率 <90% 的井拒绝自动决策。

## 8. 关键实测（全部可复现）

| 场景 | 结果 | 复现命令 |
|---|---|---|
| 分析问答 | 6 问全通，含 3 个陷阱；比率加总自动改写 | `analytics_agent.py` |
| 决策 | 24 井：缩短时率 10、维持 6、建议关停 5、升级人工 3；节电 1 885 kWh/d、产液保持 85% | `decision_agent.py` |
| 沙箱闭环 | 产液 +65.5%、吨液电耗 −7.8%、启停 −45%、净 +1.1 万元/日 | `sim\run_production.py` |
| 闭环标定 | 电耗预测偏差 11.9% → 9.3% → 5.0% | `closed_loop.py` |
| 门禁 | 决策 conforms=True；坏决策拦 13 条 | `well_validate.py` |
| 规模 | 10 000 井决策 25 ms/轮，~40 万条/秒 | `scale_test.py` |
| 预判 | 24 井 → 20 条风险（2 critical 立即） | `fault_predict.py` |
| 派工 | 6 单 → 完成 4 / 升级 1 / 拒单 1 | `dispatch.py` |
| AI 班报 | 真模型通过核对；编造版被拒并回退模板 | `report_ai.py --check` |

> 所有数字来自**合成台账与仿真**。换真实数据后必须重跑标定，不能直接引用。

## 9. 成熟度与已知限制

| 模块 | 成熟度（自评） | 主要差距 |
|---|---|---|
| 口径本体 | 70% | 指标需从 18 扩到 300+，owner 签字流程未建 |
| 分析 Agent | 75% | 无感知层模型（泵况/异常检测），解释层是模板 |
| 决策规则 | 60% | `qi` 粗估、无启停成本项、阈值未按区块标定 |
| 闭环标定 | 50% | 只在仿真里标过，真实回采链路未通 |
| 控制接口 | 40% | 执行器是模拟器，功能安全（SIL）论证空白 |
| 故障预判 | 55% | 判据靠手调阈值，缺回执反标定与命中率考核 |
| 安全合规 | 20% | 基本空白 |

**到生产的硬缺口（按阻塞程度）**：数据接入 4–8 人周 → 执行器 2–4 周/站 →
指标治理 3–6 月（并行）→ 阈值标定 4–6 周/区块 → 安全论证 2–3 月（并行）。
**单厂 MVP 6–9 个月，全域 18–24 个月。**

## 11. 下一步（按性价比排序）

1. **判据层**：`qi` 反演换 IPR 拟合；目标从 `duty` 改为沉没度窗口；启停成本进目标函数。
2. **感知层**：功图分类（供液不足/气影响/凡尔漏/断脱）轻量 CNN，边缘推理，只输出标签。
3. **优化层**：规则 → MPC-lite（24–48h 滚动，MILP，单井可并行）。
4. **学习层**：工单回执反标定阈值；预判命中率/误报率做成考核。
5. **工程化**：`DataSource` 接实时库、`Actuator` 接 OPC UA、审计接合规审计库。

> **它把"数据怎么算、井该不该开、坏了谁去修"这三件事，变成了可复算、可审计、可学习的流程。**
> 模型只在最窄的缝里帮忙——把话听懂、把话写顺；判断与责任仍然留在人这边。
